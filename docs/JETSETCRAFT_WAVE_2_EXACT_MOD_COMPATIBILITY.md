Status: **Wave 2A curation complete** for Alex's Mobs, Alex's Caves, and L_Ender's Cataclysm on the JetSetCraft Minecraft 1.20.1 / Forge 47.4.23 / Java 17 line.

This is a data/compatibility contract, not permission for JetSetCraft to take ownership of another mod's entities. Provider AI, navigation, target selection, variants, taming/owner UUIDs, boss state, loot, structures, animations, and combat remain provider-owned. JetSetCraft contributes optional social identity, reversible Street Gear presentation, challenge metadata, reputation, stingers, and graffiti rewards.

## 2. Non-negotiable compatibility behavior

1. **No hard provider class links.** Provider detection is mod-ID + `ResourceLocation` + safe capability/tag/reflection seams only. A missing provider is a dormant adapter, never a linkage error.
2. **No AI replacement.** Never remove/replace goals, path navigation, target selectors, boss controllers, ownership, source attributes, or source renderers. JetSetCraft challenge motion is an event-bounded overlay that yields immediately when provider combat/special state owns the entity.
3. **No full-registry work every tick.** Roster discovery happens on startup/data reload, is cached per server, and entity interaction remains event-driven.
4. **Multipart entities are parent-only.** Parts/segments never create independent gang membership, reputation, Street Gear, challenge targets, drops, or graffiti unlocks. They resolve to the provider parent or are ignored.
5. **Boss safety is explicit.** A boss/legendary entity with an active boss controller, hostile combat target, invulnerability/cutscene phase, scripted arena state, death animation, or source-owned mount action cannot be challenged. JetSetCraft never suppresses the source error/state to force play.
6. **Tamed/owned entities preserve ownership.** Owner UUID, sitting/follow state, inventory, variants, and provider commands survive equip, challenge, chunk reload, restart, and unequip. Server policy can require owner consent before a challenge involving a pet.
7. **Water/flight/serpentine anatomy is first-class.** The rig profile chooses skates/board/hover/contact presentation that makes anatomical sense; it never assumes two humanoid feet. If no safe rig exists, gameplay remains available with a non-invasive board/hover presentation or Street Gear is refused with a clear reason.
8. **Unknown future mobs stay fun.** Safe unrecognized `Mob` types receive generic atlas identity immediately. Curated data only upgrades presentation/rewards; it never becomes a compatibility gate.
9. **Server authoritative, client tolerant.** Persistent membership and challenge state are server-owned. Clients missing optional provider assets or a bespoke art resource use JetSetCraft fallback presentation without desync.
10. **Provider upgrades are fail-open.** A changed fingerprint logs one actionable warning, keeps known IDs curated when still present, sends unknown safe Mob IDs through generic compatibility, and never binds an old curated record to a different entity path.

## 6. Family art grammar and progression

Every row above is an exact curated gang record with a unique stable `gang_id`. `crew_family_id` creates shared social flavor without collapsing the individual record. Family style can share palette/visual grammar, but each gang must ship a distinct silhouette/motif and its own three-step reward path:

1. **Mark** - compact sticker/handstyle readable on a single block face.
2. **Throwie** - two-to-four-block fast piece that combines the gang silhouette with its family grammar.
3. **Masterpiece** - larger bespoke composition with no generic crown/badge/template reuse.

The `Bespoke graffiti motif` column is the minimum art brief for that gang. Generated or hand-authored assets must remain readable at Minecraft texture scale and may not be satisfied by a recolor-only variant.

## 7. Runtime roster verification contract

At server start or data reload, compute a provider fingerprint over sorted safe Mob `ResourceLocation`s plus provider version. For Wave 2A expected safe sets are 90 / 43 / 39. Verification behavior:

- exact match -> curated status `EXACT`;
- known IDs present plus additional safe Mob IDs -> curated known IDs + generic records for additions, status `FORWARD_COMPAT`;
- known ID missing -> that record becomes dormant, its history remains preserved, status `ROSTER_DRIFT`;
- mod absent -> all provider records dormant, status `ABSENT`;
- technical part appears in discovery -> hard-hidden before generic fallback;
- duplicate/renamed IDs are never guessed or rebound by display name.

This check is bounded to startup/reload and does not add a tick-time scan.
